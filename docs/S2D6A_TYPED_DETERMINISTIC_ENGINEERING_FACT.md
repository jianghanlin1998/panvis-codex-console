# S2D6a typed deterministic engineering fact contract

S2D6a defines the strict public `DeterministicEngineeringFactDataSchema` vocabulary for a future trusted deterministic evidence producer. It applies only to `ENGINEERING_FACT` and has exactly four V1 fact types:

- `REPOSITORY_COMMIT`: `repository`, `observedRef`, and `commitSha` record that a named ref was observed at one exact commit. Rendering uses observation semantics and never describes a movable ref as timelessly current.
- `TEST_RUN`: `repository`, `commitSha`, `command`, `exitCode`, `testFileCount`, `testCount`, `passedTestCount`, and `failedTestCount` record one command result. Counts are non-negative safe integers and passed plus failed cannot exceed total tests. Exit code and counts imply no broader quality, security, or acceptance conclusion.
- `DIFF_FILE_SET`: `repository`, `baseCommitSha`, `headCommitSha`, and `changedFiles` record an exact changed-path set. The array permits zero through 256 paths. Paths are bounded to 1,024 UTF-16 code units, use non-empty slash-separated repository-relative segments, and reject surrounding whitespace, absolute paths, backslashes, NUL, empty segments, `.` segments, and `..` segments. Input must already be unique and strictly ascending by JavaScript UTF-16 string comparison; it is rejected rather than sorted or deduplicated.
- `RUNTIME_TOOLCHAIN`: `repository`, `commitSha`, and `components` record zero through 64 observed name/version pairs. Names are trimmed to 128 UTF-16 code units, versions to 512, and component names must be unique and strictly ascending by JavaScript UTF-16 string comparison. Version strings are observations, not compatibility decisions.

All variants reuse the accepted `RepositoryReferenceSchema` and `RepositoryCommitShaSchema`. `observedRef` is trimmed and bounded to 512 UTF-16 code units; `command` is trimmed and bounded to 4,000. Numeric fields reject negative zero in addition to fractional, non-finite, unsafe, and out-of-range values so the DATA representation remains canonical. Every object is strict. There is no custom, other, free-form, claim, payload, generic metadata, prose assertion, summary, or semantic-conclusion field. Typed meaning comes only from the discriminator and structured fields.

The schema also enforces the aggregate fixed-template rendering boundary required by accepted S2D2: every valid fact's canonical title is at most 256 UTF-16 code units and its canonical body is at most 4,000. This aggregate check includes the rendered repository representation, quoted/escaped content, SHA widths, counters, changed-file list, and runtime-component list. A structurally bounded field set that would compose into an oversized canonical conclusion is rejected by S2D6a. Rendering never truncates, drops evidence details, or rewrites them into a summary, and S2D2's accepted limits remain unchanged.

`DeterministicEngineeringFactDataSchema.parse(...)` establishes only that caller-supplied data has this typed shape. It does not prove that Git, a test command, a diff, or a runtime was inspected; authenticate an observation; establish deterministic evidence authority; or accept Promoted Context. Caller-supplied repository-looking references, provenance, source strings, DATA objects, and snapshot-shaped JSON grant no trust. Like other ordinary schema parsers, direct parsing may canonicalize away runtime reflection details such as symbol, non-enumerable, or special `__proto__` own keys; that does not grant trust. The public renderer separately requires the exact stable structural-capture boundary and fails closed for those inputs without invoking accessors.

`renderDeterministicEngineeringFact(data)` is a pure fixed-template renderer. It returns only an immutable `{ title, body }` observation or `null` for malformed or structurally unstable runtime input. Every template explicitly describes a *supplied observation*; the renderer never claims that it performed verification, a diff, a command, or a runtime probe. It uses the shared structural-capture boundary, does no LLM/NLP judgment, and reads no filesystem, Git state, network, database, environment, current time, or randomness. Rendering adds no route, kind, provenance, acceptance, trust, or verification field and creates no S2D2 candidate.

S2D3 remains unchanged: five non-engineering kinds require `HUMAN_CONFIRMATION_REQUIRED`, while `ENGINEERING_FACT` remains `DETERMINISTIC_EVIDENCE_OR_HUMAN`. This slice operationally satisfies neither branch and adds no automatic acceptance. Facts outside the typed deterministic vocabulary can continue through the existing S2D4/S2D5a human-confirmation path. S2D1 remains the sole routing authority; truth never widens visibility or ACL access.

No trusted Git/test/runtime/control-plane producer or verifier exists yet. S2D6a adds no operational probe, parser-based trust API, accepted snapshot, controller, UI action, process execution, persistence, migration, storage, Audit Event, Context Item, accepted timestamp or durable ID, retrieval, JIT Context Packet, compiler, token meter, or search/RAG. A future separately approved producer must establish observation authenticity before deterministic acceptance can exist.
