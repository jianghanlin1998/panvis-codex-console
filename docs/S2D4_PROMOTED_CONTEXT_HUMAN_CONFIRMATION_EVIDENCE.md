# S2D4 Promoted Context human-confirmation evidence

S2D4 defines one pure deterministic contract for the shape of human-confirmation evidence and its structural applicability to an otherwise promotion-eligible candidate's S2D3 authority path. The exact strict envelope contains only `evidenceType: "HUMAN_CONFIRMATION"`, a trimmed non-empty `sourceReference` of at most 2,048 characters, and an offset-aware ISO `occurredAt` canonicalized to UTC. References are opaque and timestamps receive no age, future-time, recency, or clock-skew policy.

`evaluatePromotedContextHumanConfirmationEvidence(topology, candidate, evidence)` first reuses `evaluatePromotedContextAcceptanceRequirement`. Invalid candidates, routes, and topology remain non-applicable with their S2D3 reason. For an eligible candidate, structurally valid canonical evidence is applicable through the human branch while preserving the exact S2D3 requirement: `HUMAN_CONFIRMATION_REQUIRED` for five kinds and `DETERMINISTIC_EVIDENCE_OR_HUMAN` for `ENGINEERING_FACT`. The deterministic-evidence branch remains deferred. An `OPEN_QUESTION` remains unresolved; confirmation means only that the unresolved question is important durable context.

Evidence capture validates the exact own-key set and brackets repeated prototype, key, and data-descriptor observations across three differently ordered passes. Accessors are never invoked; changing values, key presence, descriptor flags, prototypes, mixed observation states, and reflection failures fail closed. Parsing and the result use only the detached captured snapshot, never a later reread of the caller's evidence object. Stable ordinary, null-prototype, frozen, sealed, cloned, JSON-round-tripped, and transparent Proxy representations remain compatible.

Schema validity does not authenticate a human. V1 remains local-first, single-user, and bounded to one authorized Console human, but the envelope has no `actorType`, actor reference, user ID, account, role, RBAC, identity-provider, session, signature, boolean confirmation, or trust field. A model or system can physically construct the same JavaScript shape without creating authority. A future trusted human-action command or controller must establish that the envelope came from the authorized human-action boundary.

Evidence is evaluated alongside the candidate. It has no candidate ID, hash, digest, fingerprint, or independently portable proof semantics. A future actual acceptance transition must atomically bind the canonical candidate and validated human-confirmation evidence into its accepted result.

The returned applicable result contains only `structurallyApplicable: true`, the unchanged S2D3 `requirement`, the closed structural-applicability reason, and a detached frozen canonical evidence snapshot. Non-applicable results contain only `structurallyApplicable: false` and a closed reason. No result claims accepted, approved, trusted, verified, authority-satisfied, or confirmation-satisfied state.

Generic `AuditEvent`, `AuditActorType`, `SubtaskImplementationCheckpoint`, and `ContextAuthority` contracts are unchanged and are not human-confirmation evidence. S2D4 creates no acceptance transition, accepted snapshot or record, rejection flow, ID, persistence, SQL, migration, storage API, Audit Event, or Context Item. It performs no filesystem, network, Git, current-time, environment, randomness, or other I/O. Retrieval, compiler and Context Packet integration, QA-profile changes, and raw-ACL changes remain deferred.
